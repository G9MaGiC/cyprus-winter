## Repo-wide i18n audit — 2026-03-17

This document summarizes remaining i18n gaps and proposes a staged migration plan for the Cyprus Winter app.

### 1. High-level summary

- **Foundation is solid**: `next-intl` is wired correctly (server and client), messages live in `messages/{locale}.json`, and core navigation text is largely localized.
- **Remaining work is mostly content extraction**:
  - Marketing/guide copy, topic pages (beaches, villages, guides), and weather/trails explanatory text are still hardcoded in English.
  - Many **ARIA labels**, **placeholders**, and **CTA labels** are hardcoded even where `useTranslations` is already used.
  - Several **API and client-side error messages** return English strings that bubble up to users.
- **Formatting**: dates, relative times, and numbers are mostly localized via shared helpers, with only a few internal uses of fixed locales.

---

### 2. Gaps by category & area

#### 2.1 Core navigation & layout

**Status**: Nav labels, footer links, and breadcrumbs are already localized via `nav.*` and `common.*` namespaces. Remaining gaps are small but important:

- **Back/skip patterns**
  - `BackLink` and `SmartBackLink` now use `common.back` / `common.backTo`, but some call sites still pass hardcoded labels (e.g. path-specific labels like `"Back to account"`).
  - Skip-to section links on home (`HomePageContent`) use hardcoded section names (`"Editors picks"`, `"Plan your day"`) in the link text.

**Recommendation**

- Standardize back labels via `common.backTo` and localized route labels (`nav.*`).
- Add a small `home.skipTo.*` namespace for the skip-to section names.

#### 2.2 Page heroes & primary CTAs

These are high-visibility and should be localized early.

- **Home**
  - `src/app/_home/HomeHero.tsx`: Marketing copy and hero CTAs (title, subtitle, seasonal line, “Ask your guide”/“Plan your trip”) are hardcoded.
  - `src/app/_home/HomeWeatherStrip.tsx`: ARIA and strip copy partly hardcoded.
- **Trails**
  - `src/app/(padded)/trails/[id]/page.tsx`: Tab labels (`Overview`, `Conditions`, `Map`, etc.), section titles, and descriptive copy (safety, “Top sights”, “Winter safety”) are hardcoded.
  - `src/app/(padded)/trails/TrailsTipsSection.tsx`: “Build a day — add trails to your plan” still inline.
- **Weather**
  - `src/app/(padded)/weather/page.tsx` and `[month]/page.tsx`: Page titles, section headings, and explanatory paragraphs are hardcoded English.
- **Topic pages**
  - `src/app/(padded)/beaches/page.tsx`, `villages/page.tsx`, `guides/troodos-december/page.tsx`, `airport/page.tsx`, `wineries/page.tsx`, `secrets/page.tsx`, `team/page.tsx`: hero titles and descriptions are all inline English text.
- **Bookings / account**
  - `src/app/(padded)/bookings/page.tsx`: Page titles, section headers (`Today`, `This week`, `Later`, `Past & cancelled`, “Plan your next visit”, “Book more”), and explanatory copy are in English.
  - `src/app/(padded)/account/page.tsx`: Account page titles and section copy now have keys in messages, but some CTAs and subtitles may still be passed as literals in other components (e.g., account settings).

**Recommendation**

- Add dedicated namespaces for each major page:
  - `home.hero.*` (already partially present but not fully used)
  - `trails.page.*`
  - `weather.page.*`
  - `beaches.page.*`, `villages.page.*`, `guides.page.*`, `airport.page.*`, `wineries.page.*`, `secrets.page.*`, `team.page.*`
  - `bookings.page.*`, `account.page.*`
- For each, localize:
  - Hero title, subtitle, body/intro paragraph.
  - Primary CTAs and key ARIA labels (`home.aria.*`, `trails.aria.*`, etc.).

#### 2.3 Forms & validation

- **Booking forms**
  - `src/app/(padded)/book/winery/[id]/WineryBookingForm.tsx` and `book/guide/[id]/GuideBookingForm.tsx`:
    - Placeholders such as `"John Smith"`, `"john@example.com"`, and notes fields are hardcoded.
    - Error messages like `"Something went wrong — check your connection and try again."` are in English.
- **Auth**
  - `src/app/(padded)/login/page.tsx`, `register/page.tsx`, `reset-password/page.tsx`:
    - Error-normalization helpers return English strings for invalid email, email confirmation required, generic error (“Something went wrong. Try again.”).
  - `Reset password` password placeholders (`"••••••••"`) are not locale-sensitive per se but could be keyed for consistency.

**Recommendation**

- Introduce `forms.*` and/or path-specific namespaces:
  - `booking.forms.*`, `auth.forms.*`, `auth.errors.*`.
- Move:
  - All field labels and placeholders (names, email, notes) to messages.
  - Error messages into stable keys used across auth and booking flows.

#### 2.4 Empty states & banners

- **Bookings**
  - `src/app/(padded)/bookings/page.tsx`:
    - Empty-state copy (`"No bookings yet"`, explanations and CTAs), as well as “tomorrow” highlight banner and “Plan your next visit” block, are hardcoded.
- **Trails**
  - `src/app/(padded)/trails/[id]/page.tsx`:
    - Empty conditions text and “Be the first to report” CTA are inline.
- **Home & other banners**
  - `src/components/TripReminderBanner.tsx` has been localized via `plan.tripReminderBanner`, but similar banners and strips may still be inline in `_home` modules.

**Recommendation**

- Extend `bookings.*`, `trails.*`, and `plan.*` namespaces with:
  - `bookings.emptyState.*`, `bookings.groups.*`, `bookings.nextVisit.*`.
  - `trails.conditions.empty.*`.
- For banners/strips on home and other pages, use a `*.banners.*` sub-namespace.

#### 2.5 ARIA / alt text & accessibility

- Many ARIA labels and alt texts are **still hardcoded**:
  - `HomeWeatherStrip`, `HomeSearchSection`, `PlacePicker`, `DiscoverFilterBar`, `TrailsFilterBar`, `SearchBar`, `OnboardingModal`, etc.
  - Examples: `"Search places by name or region"`, `"Browse places to add to your day"`, `"Filter places"`, `"Scroll to map of places"`, `"Start exploring places and trails"`, `"Skip onboarding"`.
- Trail and hero images sometimes use English alt strings inline (e.g., Omodos village description).

**Recommendation**

- Consolidate ARIA/alt text into structured sub-namespaces:
  - `home.aria.*`, `discoverPage.aria.*`, `trails.aria.*`, `bookings.aria.*`.
  - `ui.hero.*.imageAlt` for hero imagery, or per-page `*.hero.imageAlt`.
- Use `t("ns.key")` for ARIA labels and keep `<bdi>` and `dir` semantics as already introduced.

#### 2.6 API / backend errors

- **Rate limiting & generic server errors**
  - `/app/api/right-now/route.ts`, `/app/api/push/vapid/route.ts`, `/app/api/weather/route.ts`, `/app/api/track/route.ts`, `/app/api/stats/route.ts`, `/app/api/bookings/route.ts`, `/app/api/trail-reports/route.ts`, `/app/api/chat/route.ts` all contain English error strings such as:
    - `"Too many requests. Try again in a minute."`
    - `"Failed to load stats"`
    - `"We couldn't complete your booking. Please try again."`
    - `"We couldn't save your report. Please try again."`
    - `"Something went wrong. Please try again."`
- **Client-surfaces for errors**
  - `RightNowNearYou`, `BookingsPage`, `useAIChat`, `ErrorState` repeat similar error wordings client-side, again as English literals.

**Recommendation**

- Introduce a shared `errors.*` namespace:
  - `errors.common.somethingWentWrong`
  - `errors.common.rateLimited`
  - `errors.bookings.createFailed`
  - `errors.trails.reportFailed`
  - `errors.stats.loadFailed`
- Ensure API routes use error codes consistently and map them to message keys at the boundary (either server-side using `locale`, or client-side through `t("errors.*")` based on a stable `code`).

### 3. Namespace & pattern recommendations

Based on current usage and gaps, the following structure will keep things consistent:

- **Core**
  - `common.*` — global UI primitives (buttons, back/skip, generic errors, accessibility helpers).
  - `nav.*` — navigation labels and ARIA for nav.
  - `meta.*` — page titles/descriptions for metadata where relevant.
- **Pages / flows**
  - `home.*` and `home.hero.*`, `home.search.*`, `home.startHere.*`.
  - `trails.page.*`, `trails.conditions.*`, `trails.banners.*`.
  - `weather.page.*`, `weather.month.*`.
  - `beaches.page.*`, `villages.page.*`, `guides.page.*`, `airport.page.*`, `wineries.page.*`, `secrets.page.*`, `team.page.*`, `terms.page.*`.
  - `plan.*`, `bookings.*`, `account.*`, `search.*`.
- **Support**
  - `forms.*` and/or nested under flows (`booking.forms.*`, `auth.forms.*`, `auth.errors.*`).
  - `errors.*` — cross-cutting error catalog for API and client.
  - `*.aria.*` and `*.hero.imageAlt` — accessibility-specific keys.

Patterns to follow:

- Server components: `const t = await getTranslations({ locale, namespace: "ns" });`
- Client components: `const t = useTranslations("ns"); const locale = useLocale();`
- Formatting:
  - Use `formatDate(dateStr, locale)`, `formatReportedAgo(iso, locale)`, and `Intl.NumberFormat(locale, …)` instead of manual formatting or `toLocaleString()` without locale.
- Plurals:
  - Use ICU messages in `messages/*.json` and `t("ns.key", { count })` instead of inline ternaries.

### 4. Staged migration plan

#### Stage 1 — High-traffic, user-critical surfaces

**Goal**: Localize the core experience so users on non-English locales see coherent, localized copy in the main flows.

**Targets**

1. **Home**
   - `src/app/_home/HomeHero.tsx`, `HomeSearchSection.tsx`, `HomeWeatherStrip.tsx`:
     - Move hero title, subtitle, seasonal line, CTAs, and search placeholder into `home.*` (e.g., `home.hero.title`, `home.hero.subtitle`, `home.search.placeholder`).
   - Skip links in `HomePageContent`:
     - Add `home.skipTo.*`.
2. **Trails**
   - `src/app/(padded)/trails/[id]/page.tsx`, `TrailsTipsSection.tsx`, `TrailBadges.tsx`:
     - Localize tab labels, section headings, safety copy, “Top sights”, and conditions messaging under `trails.page.*` and `trails.conditions.*`.
3. **Weather**
   - `src/app/(padded)/weather/page.tsx`, `[month]/page.tsx`:
     - Localize titles, table headings, and explanatory paragraphs under `weather.page.*`.
4. **Bookings & Account**
   - `src/app/(padded)/bookings/page.tsx`, `account/page.tsx`:
     - Ensure all headers, empty states, banners, and CTAs use `bookings.*` and `account.*` keys (some keys already exist; fill gaps).
5. **API / error surface**
   - Centralize shared error strings under `errors.*`:
     - Update Right Now, push, weather, track, stats, bookings, trail-reports, and chat routes to emit codes and map to translation keys.
     - Update client surfaces (`RightNowNearYou`, `BookingsPage`, `useAIChat`, `ErrorState`) to use `t("errors.*")` rather than inline English.

**Example refactor pattern**

Before:

```tsx
<h1>Cyprus Winter Weather by Month</h1>
<p>Coast and Troodos temperatures, month by month. Plan layers, trails, and wineries.</p>
```

After:

```tsx
const tWeather = useTranslations("weather.page");
<h1>{tWeather("title")}</h1>
<p>{tWeather("description")}</p>
```

#### Stage 2 — UX polish & accessibility

**Goal**: Ensure assistive technologies and secondary UX elements are localized and coherent.

**Targets**

1. **ARIA & alt text**
   - Consolidate hardcoded ARIA labels and alt text from:
     - `PlacePicker`, `SearchBar`, `DiscoverFilterBar`, `TrailsFilterBar`, onboarding, and heroes.
   - Introduce `*.aria.*` namespaces, e.g.:
     - `home.aria.search`, `discoverPage.aria.filter`, `trails.aria.conditions`.
2. **Secondary banners & strips**
   - Ensure all strips and banners (Right Now, safety reminders, onboarding hints) use localized messages under `*.banners.*` or existing page namespaces.

#### Stage 3 — Long tail & admin

**Goal**: Localize low-traffic or admin-only surfaces and clean up remaining debt.

**Targets**

1. Admin and tooling
   - `src/app/(padded)/admin/stats/page.tsx`, any admin-specific pages: move remaining copy into `admin.*`.
2. Legal text
   - `terms/page.tsx`, `privacy/page.tsx`:
     - Decide whether these should be translated or remain English-only per legal constraints; if translating, move into `terms.page.*` and `privacy.page.*`.
3. Legacy/internal helpers
   - Review internal uses of fixed locales (e.g., `"en-CA"` in `right-now` buckets) to confirm they cannot leak to users; if they can, apply standard helpers.

### 5. Risk & impact

- **Risky areas**
  - Shared components like `TrailCard`, `TrailBadges`, `SearchBar`, `PlacePicker`, and `ErrorState` are used widely; their i18n refactors should be done in small, carefully tested PRs.
  - API error mapping changes should be coordinated so that both server and client agree on error codes and no user-facing message is lost or downgraded.
- **Localization complexity**
  - Polish plurals are already handled in some places (e.g., `common.peopleCount`, countdown banners). New pluralized messages (e.g., days/weeks counts, multi-item lists) should follow the same ICU pattern and be tested with `pl`.
  - Mixed dynamic/static content (e.g., “Hike in the morning, village or winery in the afternoon. Start by 9am.”) should be moved into full-sentence translations, not reconstructed via concatenation.
- **RTL & future locales**
  - `dir` and bidi-aware patterns (e.g., `.rtl-flip`, `.breadcrumb-ol`) are already in place; new components should use those patterns rather than hardcoded left/right styling or arrows.

---

### 6. Suggested PR slicing

To keep review manageable:

1. **PR 1 — Trails & Weather i18n**
   - Localize trails detail/list conditions and weather pages.
2. **PR 2 — Bookings & Account i18n**
   - Migrate bookings and account copy (including error messages and empty states).
3. **PR 3 — Home & topic pages i18n**
   - Home hero, search, weather strip, and topic page heroes (beaches, villages, guides, airport, wineries, secrets, team).
4. **PR 4 — Errors & API surface**
   - Introduce `errors.*` namespace and wire server + client error handling.
5. **PR 5 — Accessibility & ARIA**
   - Consolidate ARIA/alt strings and remaining banners/strips.

Each PR should update `messages/en.json` (and ideally `de/el/pl` in the same commit), run `npm run i18n:validate`, and keep to the patterns and namespaces outlined in `docs/I18N_GUIDE.md`.
